# OctoAcme Process Documentation Index

This directory contains the project management and delivery process guidance used across OctoAcme workstreams.

## Overview

These documents are designed to make project delivery practices easy to discover, consistent across teams, and usable as context for Copilot Spaces and other project tooling.

## Available process docs

- [octoacme-project-management-overview.md](./octoacme-project-management-overview.md) — high-level overview of roles, artifacts, and the project lifecycle
- [octoacme-project-initiation.md](./octoacme-project-initiation.md) — validates the need, aligns stakeholders, and confirms readiness to plan
- [octoacme-project-planning.md](./octoacme-project-planning.md) — turns the approved initiative into a delivery-ready backlog and roadmap
- [octoacme-execution-and-tracking.md](./octoacme-execution-and-tracking.md) — covers daily execution, tracking, quality, and escalation
- [octoacme-risks-and-communication.md](./octoacme-risks-and-communication.md) — defines risk management and stakeholder communication expectations
- [octoacme-release-and-deployment.md](./octoacme-release-and-deployment.md) — standardizes release readiness, deployment, and rollback practices
- [octoacme-retrospective-and-continuous-improvement.md](./octoacme-retrospective-and-continuous-improvement.md) — captures lessons learned and turns them into improvements
- [octoacme-roles-and-personas.md](./octoacme-roles-and-personas.md) — defines common personas and responsibilities used in the program docs

## How to use this library

- Start with the overview document for a quick introduction to the process model.
- Use the initiation and planning guides when a project is newly proposed or being scoped.
- Refer to execution and release docs during day-to-day delivery and stakeholder updates.
- Use retrospectives and risk communications to improve delivery quality over time.

## Recommended practice

Keep these docs lightweight, practical, and tied to actual team workflows. When a process is not working in practice, update the documentation and capture the rationale so the knowledge remains explicit and usable by the whole team.
